# نجم نت — صفحة HotSpot

بوابة MikroTik HotSpot مستقلة، تعمل محليا من ملفات HTML/CSS/JavaScript وتتضمن تسجيل الدخول برقم الكرت، حالة الجلسة، آخر كرتين، الأسعار، نقاط البيع، تعليمات الاستخدام، التصوير، ودعم العملاء.

## النشر على الراوتر

1. ارفع **محتويات المجلد** مع الحفاظ على المسارات `css/` و`js/` و`font/` و`img/` إلى مجلد HotSpot مخصص على MikroTik RouterOS.
2. حدد هذا المجلد في إعداد `html-override-directory` لملف تعريف HotSpot المناسب، بعد أخذ نسخة احتياطية من الصفحة الحالية.
3. تأكد من عمل طريقة المصادقة المستخدمة فعليا. القالب الحالي يرسل رقم الكرت في خانة `username` باستخدام طلب `POST` بدون كلمة مرور؛ لم يتم تغيير منطق هذا الإعداد. **إذا كان الراوتر يعمل بطريقة HTTP-CHAP فقط، فلا تستخدم الصفحة قبل إضافة ومعاينة دعم CHAP على الراوتر الفعلي**، لأن CHAP يتطلب قيمة `chap-id` وتحديا ومجموع MD5 حسب توثيق MikroTik. يفضل HTTPS للمصادقة عندما يتوفر.
4. اختبر كرتا صالحا، وكرتا خاطئا، وكرتا منتهيا، وكرتا متصلا بجهاز آخر، وانقطاع RADIUS، والخروج، وإعادة الدخول. نتائج المحاكاة لا تغني عن الاختبار على الراوتر الحقيقي.

## ملاحظات الإصلاح (21 نوفمبر 2026)

- الاستمرار في تهيئة الصفحة حتى عندما يمنع المتصفح وصول JavaScript إلى `document.cookie`؛ هذا مهم لبوابات Wi-Fi المقيدة.
- عدم وصف فشل الاتصال بخادم RADIUS بأنه كرت خاطئ أو منتهٍ.
- إمهال تأكيد الجلسة عند رد `onLoginStart` غير الحاسم، دون إرسال طلب دخول مكرر.
- إضافة ألوان وخلفيات احتياطية لمتصفحات Android القديمة التي لا تدعم CSS custom properties، وإزالة محدد CSS قديم/مكرر غير مدعوم.
- معالجة عرض الهواتف الصغيرة وإبقاء زر الدخول مرئيا دون تمرير أفقي في عرض 240–430 بكسل أثناء الاختبارات.
- إبقاء ملف الكاميرا `js/cam.najm.js` والشعار ومحتويات الباقات ونقاط البيع كما وردت في المصدر.

## الاختبارات

التحقق المحلي:

```sh
node --test tests/portal.test.cjs
```

تجري GitHub Actions اختبارات JavaScript وملفات البوابة عند كل دفع إلى `main` أو فروع الإصلاح وعند طلبات الدمج. لا يوجد برنامج Windows أو ملفات تثبيت في هذا المشروع، لذلك لا تنطبق عليه دورة إنتاج Portable/Installer.
